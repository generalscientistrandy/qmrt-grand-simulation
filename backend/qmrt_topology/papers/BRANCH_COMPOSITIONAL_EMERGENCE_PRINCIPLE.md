## Core Principle

> **"QMRT emergence is branch-compositional: higher-order phenomena are produced not by isolated mechanisms alone, but by branches with distinct purposes interacting on different timescales under shared energetic constraints."**

---

## The Pattern

Throughout the simulation program, a consistent pattern has emerged:

| Isolated Test | Result | Branch-Role Clarification | Result |
|---------------|--------|---------------------------|--------|
| Reduced model | Convincing | Full τ added | Different interpretation |
| Dimensional behavior | Ambiguous | Driving + development + oscillation | Clear |
| Balance | Unexplained | Symmetric creation + attractor | Explained |
| τ-lifetime | Weak (r=-0.05) | Time evolution + birth environment | Strong (20%) |
| Phase coupling | Failed | — | Closed as insufficient |

**Isolated mechanisms often look weak, partial, or negative — even when the deeper behavior emerges from coupled interactions.**

---

## Why This Happens

The medium does not behave like a set of independent knobs. It behaves like a **coupled developmental system**:

```
One mechanism creates a possibility
    ↓
Another stabilizes it
    ↓
Another limits it
    ↓
Another determines when it matters
```

A single mechanism tested alone may fail not because the idea is wrong, but because **it is only one part of a coupled architecture**.

---

## Interpreting Negative Results

Negative single-mechanism tests should be interpreted as:

| Interpretation | Meaning |
|----------------|---------|
| ✓ Failure of **sufficiency** | This mechanism cannot work alone |
| ? Failure of **relevance** | May still matter in coupled context |
| ✗ Automatic rejection | Premature without role clarification |

**The correct lesson is not "single tests are useless."**

It is: **Single tests are useful for ruling out sufficiency, but not automatically for ruling out necessity inside a larger coupled system.**

## The Time Example

Time did not emerge because one "time variable" suddenly worked.

It emerged because different **time-functions** were separated by role:

| Time-Function | Role |
|---------------|------|
| Developmental ordering | When structures form |
| Oscillatory cycle timing | Periodic dynamics |
| Event sequencing | Causal order |
| Branch activation timing | When mechanisms engage |
| Maintenance/collapse timing | Persistence dynamics |

Once separated by role, time stopped looking like a failed single mechanism and started looking like **a coordinated multi-branch structure**.

## Branch Analysis Framework

For any proposed mechanism, ask:

### 1. What branch is this?
- Creator (generates structure)
- Stabilizer (maintains structure)
- Regulator (limits growth)
- Sorter (organizes structure)
- Timer (controls activation)

### 2. What is its purpose?
- Create structure?
- Stabilize structure?
- Limit growth?
- Carry memory?
- Sort organization?
- Regulate energy?

### 3. What is its timescale?
- Early formation?
- Mid-transition?
- Late consolidation?
- Only under driving?
- Only during collapse/rebuild?

### 4. What are its interaction partners?
- Geometry?
- τ accounting?
- Topology?
- Channel structure?
- Oscillatory timing?
- Density/packing?

### 5. What is its failure mode?
- Weak effect alone?
- No effect alone?
- Artifact?
- Misplaced role?

## Implications for Future Work

### Do:
- Use single tests to ask: "Can this work by itself?"
- Use coupled tests to ask: "What happens in combination?"
- Identify branch purpose before declaring failure
- Stay open to mechanisms reappearing in coupled contexts

### Don't:
- Automatically reject failed single-mechanism tests
- Rescue every failure by saying "it needs friends"
- Force a branch to do the whole job alone
- Conflate sufficiency failure with relevance failure

But this principle means:
- Phase coherence may still matter later
- It would matter as one branch within a larger coupled structure

> "Minimal local phase coupling as a **sufficient** mechanism"

> "In this simulator, isolated mechanisms are often insufficient even when they may be contributory. Negative single-mechanism tests should therefore be interpreted as failures of sufficiency, not automatically failures of relevance within a broader coupled architecture."
